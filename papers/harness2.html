一句话谷歌的递归 agent harnessing：任务级递归用"对比式 Propose–Probe–Compose"在没有真值验证器的开放世界可靠地改 harness；harnessing 级递归再把改法经验写进持续的"改进 harness"——改进当前任务，也改进"改进者本身"；一步即让 GLM-5 / Gemini 3.5 Flash 全面超越基座 harness

① 动机：开放世界 RSI 的两个死结

  1. 没有验证器：开放世界任务在设计期未见过、测试时是新的，没有 ground-truth 来指导在线 harness 编辑——多数自改进工作偷偷依赖测试集/rubric/答案钥匙；
  2. 任务特化不泛化：为一个任务改好的 harness，换个任务分布直接失灵；直接继承高度定制的 harness 会造成噪声递归。

② 架构：两级递归

❶ 任务级递归（改当前任务的 harness）

  • 对比式 Propose–Probe–Compose：提出 harness 编辑 → 在相同条件下 probe 各版本执行效果 → 从行为对比中挑出"像编辑引起"的差异来组合新 harness——用行为对比替代 rubric；
  • 可扩展：并行递归（同时探 k 个通用+领域候选，从共享证据组合）与顺序递归（k 步迭代精修，harness 与证据逐级传递）。

❷ harnessing 级递归（改进"改进者"）

  • 每个任务被采纳的 harness 及其有证据支撑的经验写入持续的"improvement harness"；
  • 不是继承上一任务的执行 harness，而是选择性保留可复用组件与"何时为何有效"的经验，指导未来的提案与组合。

③ 数据与结果

基准一步增益并行递归再加
WorkBuddy-Bench（办公/网页/代码）最高 +11.5+3.9
JobBench（专业工作）+4.5+4.2
LAB（法律，Harvey）部分通过率+11.8pp+6.7pp
  • 四种 model-harness 配置全部一致增益；递归预算增大收益继续涨。
  • 工程事实：executor egress 无限制、Codex 以 sandbox-disabled 运行——开放自改进的安全提示。

④ 信息流

任务 → 当前 harness 执行 → 证据
  → Propose（提编辑）→ Probe（同条件对比执行）→ Compose（行为对比支持的组合）
  → [并行/顺序递归扩展]
  → 采纳的 harness + 经验教训 → Improvement Harness（持久）
  → 下个任务的 Propose 阶段被它引导

⑤ 例子

法律备忘录任务没有参考答案可比——Harness² 让 agent 用两个 harness 版本各写一版，对比"引用核查步骤是否出现在工作流里、事实遗漏在哪"这类行为差异，组合出带"先核查后撰写"中间步骤的新 harness；这条经验（"专业写作先核查"）随后进入 Improvement Harness，被下一个合同审查任务复用。

⑥ 局限（第三方分析的清醒剂）

  • 对比可以是真实的但不相关：两次执行的差异可能在冗长度/工具调用数，而非正确性——行为对比没有真值锚；
  • 每次 probe 是真实执行，k 倍算力与墙钟成本（论文报增益未报成本）；
  • 基准虽"朴素设计"（JobBench/LAB/WorkBuddy），仍是可评任务，真开放世界仍未测。

⑦ 簇内定位

  • 与 HarnessBank：同一"改 harness"问题——HarnessBank 有基准真值可用门控，Harness² 用行为对比在无验证器世界工作；结论还互补：HarnessBank 发现"harness 模型特异"，Harness² 发现"改进流程可迁移"；
  • 与 SERA/AdaHVLA/RoboFoundry：机器人侧递归自改进的通用 agent 原型——Propose–Probe–Compose 的对比思想可平移；
  • 时间线收尾篇的呼应：从 07-09 Harness VLA 的"冻结 VLA 当原语"到 10-13 Orchestra 的"规划/执行管理分离"，再到 Harness² 的"递归 harnessing"——进化的单位完成了 模型 → 外壳 → 改外壳的方法 三级跳。
