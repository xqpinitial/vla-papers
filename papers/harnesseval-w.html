项内容
一句话把 LLM 生态的 harness 范式接到世界模型评测：父 agent 解读案例→拆成可测子问题→调度带诊断工具的子 agent 取证→校验汇总成可审计证据树——18 个世界模型 × 330 案例，Intentional 维与人类 Bradley–Terry 排序 Spearman ρ=0.93
冻结被评测的 18 个世界模型；评测管线本身开源（Apache-2.0，harnesseval CLI：eval/plan/generate/verify）
演化开放技能库与评测案例，邀请社区扩展（live benchmark）
三轴Render（观测质量）/ Transition（干预下状态转移）/ Persistence（长程世界持续性）

① 动机：基准不该只给一个标量分

  • 评测的可信度在于支撑分数的推理链。世界模型 rollout 的评判需要理解物理、因果、世界状态是否正确演化——人类一眼能发现的违规，现有基准却用暴力指标计算，没有可检查、可验证的推理链。
  • harness 的定义（本文给得很清楚）：不只是代码包装，而是把"取证/用工具/推理"这类人类评测工作流形式化为可执行 agent 脚手架。

② 架构：层级 agent 评测工作流

评测案例 → 父 Agent：解读上下文 → 拆成可测子问题（按案例路由技能）
  → 子 Agent × N：各带定制上下文 + 诊断工具（视觉 grounding 等）
     对自己的子问题独立取证打分
  → 父 Agent 校验证据 → 汇总最终判定
  → 产出 evidence tree：测了什么 / 哪个工具提供视觉依据 / 完整逻辑链
  • 技能库：11 个 skill（仓库 src/harnesseval/ 含 planner、runner、metric backends）；
  • 形式化：未来观测分布由隐状态边缘化——观测似然 S(o_i|s_i)、动作条件转移 T(s_i|s_{i-1},a_{i-1})、由历史推断初态 P(s_0|o_{-T:0})。

③ 数据与结果

  • 18 个代表性世界模型 × 330 个评测案例（案例含初始图 + prompt + 干预），数千次打分轨迹；
  • 与人类偏好对齐：Intentional 维 Bradley–Terry 排序 Spearman ρ=0.93；
  • 细粒度诊断示例：子 agent 能指出"两只夹爪都夹住了勺子，而指令要求左夹爪保持低位 → no-extra-event 0.750 → 整体 0.913"——错误可定位到帧与干预。

④ 例子

交互式世界模型案例："按住勺子但左夹爪被要求放松"——旧指标只给总分；HarnessEval-W 的证据树显示：Sub-agent "no extra event" 给 0.582/0.750，另一个子问题满分 0.913，最终分数能追溯到底是哪个子问题失败。

⑤ 局限与边界

  • 全量 330 案例与 HF 托管在归档核查时部分待发布（管线与 demo 已开源）；V1 Leaderboard 当时 Coming Soon；
  • 评测 agent 自身依赖强 VLM——评测者的偏差需要人类对齐实验兜底（ρ=0.93 是当前证据）；
  • 面向交互式开放域世界模型，不覆盖操纵 EEF 轴的具身任务。

⑥ 簇内定位

  • 时间线上与 HumanCLAW 同月，共同把"harness"从提升能力扩展到测量能力：一个测 VLM 决策，一个测世界模型预测；
  • 与 CaP-Bench：CaP-Bench 评 coding agent（固定量表分层），HarnessEval-W 评生成式 rollout（推理链证据树）——评测 agentic 化的两个方向；
  • 呼应 ASPIRE/HarnessPAI 的门控哲学：没有可验证的推理链，分数就不可信——这句话同时适用于评模型和评 harness 改动。
