速览

项内容
一句话把任务规划与执行管理从动作生成中分离的 agent harness：完整多模态指令 → 有序子任务分解 + 实体 grounding 更新 + 共享执行上下文；动作策略管"怎么做"，独立训练的进度评估器管"什么时候算完成、何时进入下一步"——RMBench 九任务 68.22%（超 Mem-0 26.22pp）；RMBench-Compose 的 ASL 达 7.35 个子任务 = HarnessVLA 的 2.46 倍
冻结动作策略（含 π₀.₅ 系） + 进度评估器为独立训练组件
演化无自进化；卖点是分工架构本身
基准RMBench（9 任务）+ 新基准 RMBench-Compose + 4 个真机多步任务

① 动机：长程失败的三种"记账错"

  • 好的局部动作也可能被浪费：做错对象 / 重复或跳步 / 过早或过晚切换子任务——编排的瓶颈在 order、grounding、transition 的协调，而非动作能力。
  • 场景例子：按 3、1、2 顺序把编号名牌摆上蓝垫——必须选对牌、守住顺序、知道每次放置何时完成。

② 架构：共享上下文 + 三角色

组件职责
Task Agent接收完整多模态指令（纯语言 / 语言+参考图 / 语言+点框提示）→ 有序子任务分解（含相关实体描述）
Visual Grounding为当前活跃步骤定位并跟踪实体（实现里用 MolmoPoint 出点提示 + SAM3 分割）
共享执行上下文活跃子任务 + 空间 grounding + 近期观测 + 任务记录 + 转换管理
动作策略用共享上下文生成动作
进度评估器（独立训练）估计当前子任务何时完成 → 决定何时推进下一步

④ 信息流

多模态指令 → Task Agent：有序子任务分解（实体绑定）
  → 活跃子任务 → Grounding（MolmoPoint + SAM3）定位实体
  → 动作策略（读共享上下文）生成动作 → 执行
  → 进度评估器：完成？→ 推进下一子任务 / 继续
  → 上下文更新（已完成步骤、物体/目标位置变化）→ 循环

④B 核心消融（诚实标注）

论文消融以图/曲线呈现，无独立组件关闭大表；核心对照是"规划/执行管理/动作生成三分"整体 vs 记忆双系统（68.22 vs 42.00，+26.2pp）与 agentic 基线 HarnessVLA（+41.4pp）。

⑤ 例子

名牌 3-1-2：Task Agent 拆出"拿 3 号→放蓝垫→拿 1 号→…"；grounding 锁定"3 号"的位置（哪怕场景被打乱后更新位置）；进度评估器在"3 号已放稳"时才允许推进——防重复、防跳步、防过早切换。

⑥ 局限

  • 进度评估器是独立训练的组件——每个域都要训练这个"账房"；
  • 无自进化：上下文与评估器不随经验成长（对比 RoboHarn-Evo/RoboFoundry）；
  • 组合泛化仍以 RMBench 族任务为主。

⑦ 簇内定位

  • 与 Harness VLA：直接对比（ASL 2.46×）——同样面向长程记账，Orchestra 把"记账"做成规划-执行管理-动作生成三者分离 + 独立进度信号，比记忆引导 agent 的单点方案更彻底；
  • 与 RoboHarness/EMERGE-Policy：都在回答"长程谁负责账本"，Orchestra 的独立进度评估器是独特贡献（其他家用 LLM 判断或判据校验）；
  • 与 EmbodiedSkills 的 Verify：Verify 是每 chunk 后的局部检查，Orchestra 的进度评估器是子任务级的"完成裁判"——两个粒度互补；
  • 时间线收官：规划/执行管理/动作生成的三分离，是"系统即策略"叙事最清晰的架构表述之一。
